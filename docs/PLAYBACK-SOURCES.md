## Non-mutating verification procedure

Use Linux Node/npm in WSL2 for this Windows-shared workspace. Run `npm run check:streams` for lightweight reachability. Only terminal **2xx** responses count as reachable; supported redirects (301/302/303/307/308) must resolve to 2xx within five hops. Unexpected 3xx, missing Location, loops, downgrades and unsafe targets fail. HEAD and its optional one-byte GET fallback share one 7.5-second deadline. This report never verifies audio.

Run `npm run probe:streams` for **two separate bounded GETs per catalogue stream**. It writes only metadata to ignored `reports/stream-probes.json`, closes bodies at the byte/time limit and never edits catalogue files. It records MIME separately from byte hints, optional decoder PCM output, redirects, timeouts, CORS header and explicitly unassessed identity/clients/permission. A timeout after HTTP headers is not a decoding pass. Nonstandard ports, geo/access controls and transient failures may make observations environment-specific. Reports can contain URLs; inspect/redact them before sharing if testing future authenticated candidates.

The default transport is native HTTPS with a shared **one-request** gate held until socket close, including callers using concurrent promises. Each probe has a 10-second deadline across queue wait, DNS, TLS, redirects and body reading, plus at most 5 seconds for the optional decoder. It follows at most five redirects (six requests) and consumes at most **131,072 application-body bytes** from a terminal GET; Range requests are sent and ignored Range responses are closed at the cap. Redirect, error and HEAD bodies are immediately destroyed without being sampled. Headers are capped at 8 KiB per response; informational responses, upgrades and compressed bodies are rejected. Two sequential probes mean at most 30 seconds per stream including decoding, before ordinary process/scheduler overhead. Catalogue batches are sequential. Options cannot increase the hard time/byte/redirect limits.

**Transfer limitation:** TCP/TLS headers, handshakes, kernel buffers and in-flight data can exceed the sampled-body byte count before the socket closes. Application code cannot guarantee an exact physical wire-byte cap. No full-broadcast download or persistent audio is performed, but use an external bandwidth/egress limiter if an absolute network-transfer quota is required. The original report's `sampledBytes` must never be interpreted as measured total network traffic.

The URL validator rejects IP literals (including normalized alternate IPv4 forms), credentials, single-label/local names, `.localhost` and local suffixes even with trailing dots. Syntax validation alone cannot establish DNS safety. For **every actual connection**, the socket lookup resolves all addresses, rejects any private, loopback, link-local/metadata, multicast, reserved or other excluded special-use address, and returns only one checked public address. This is the connection lookup itself, preventing a separate resolution from rebinding to an unchecked address. TLS still checks the original hostname. Each redirect creates a fresh checked connection, with no pooled sockets, automatic redirects, cookies, environment proxy or decompression. The conservative IPv6 policy permits ordinary global unicast and excludes transition/special-purpose ranges; it may reject otherwise legitimate special-purpose destinations. The policy is based on the [IANA IPv4 registry](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IPv6 registry](https://www.iana.org/assignments/iana-ipv6-special-registry/), and native connection controls documented by [Node HTTPS](https://nodejs.org/docs/latest-v24.x/api/https.html).

This is a curated-catalogue tool, not an arbitrary-URL public service. Keep public-address range policy reviewed as allocations change. DNS jobs may finish after an abort, but the expired lookup cannot open a socket. One approved address is selected without address failover; routing or IPv6 failures can therefore produce false-negative health results. OS routing/VPN/NAT can still route a nominally public address privately; network egress rules are the additional boundary for hostile networks. Test-only injected fetchers/resolvers bypass parts of the real transport by design and must not be supplied by untrusted runtime input.

If an already-approved FFmpeg installation is on PATH, direct samples are piped from bounded memory to it, decoded PCM counted and discarded. The decoder gets **no URL** and only the `pipe` protocol; it cannot traverse HLS playlists or fetch external resources. Output reports codec/sample rate when available and distinguishes partial decoding from two complete seconds. The script installs nothing. FFmpeg absence is `not-tested`, not `failed` audio and never `verified`.

For HLS, the separate manual procedure is: inspect the bounded master/media playlist, resolve a published variant against its final HTTPS URL, validate every redirect and referenced HTTPS resource, then inspect one short segment (including initialization data if needed) under explicit byte/time bounds. Check container/codec with an available decoder, key access where relevant and playlist refresh. Do not hand a live playlist to an unrestricted downloader or archive broadcasts. The automated probe deliberately stops at playlists; **HLS decoder verification remains manual**. An expiring or authenticated URL must not be copied to public JSON.

After technical checks, manually review the documentary broadcaster identity, audible identity where available, geographic scope, Web result, Android result and permission as separate dimensions. Only an editor can update the seven-field v1 stream record. A `verified` timestamp records a successful playback test; failed attempts belong in reports and must not refresh it. Permission is independent. No health report or weekly workflow upgrades either field.
